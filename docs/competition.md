# 赛题 · Competition brief

> 抓取时间 2026-09-25，规则版本 1.0（2026-09-09）。原始页面见文末链接；本页是 distilled 版本，
> 数字与措辞以官网为准，**评分常数与合约以入门包代码为准**（见 [scoring.md](scoring.md)）。

## 一句话赛题

给一座望远镜写一个**观测调度智能体**。它每 15 分钟（一个 900 秒时隙）决定一件事：**下一个时隙拍哪片天区，还是等。**

难处在于**部分可观测**：智能体看得见公开的天空状态（天区目录、可见窗口、几何、天文时钟、每晚整点发布的天气快照与 7 天预报、观测请求），但**看不到真实天气**、看不到仪器效率、看不到隐藏的科学标签。每个选择都是对未来的下注。

```
观测请求陆续下发 → 智能体查询天空状态 → 决定下一个时隙指向哪里 → 曝光开始
     ↑                                                            ↓
  新的观测结果 ← 真实天气由主办方模拟、事后才公开 ← 夜空持续变化
```

## 评判标准

不是「谁跑得最高分」，而是**泛化能力**：

1. **真实数据**上的成绩 —— 公开场景 `dev-reference`。
2. **隐藏场景**上的表现 —— 同一生成器、未公开的 seed / 规模 / wallclock。私有评测，成绩不公开。
3. **代码质量、文档与展示**。

这三条直接决定了工作区的形状：策略不能对 `dev-reference` 过拟合（因此 `strategies/` 的每一版都要在多场景、多 seed 上跑）；文档必须是交付物的一部分（因此有 `docs/`）。

## 提交方式

两条通道，当前 Playground 阶段以**结果提交**为主：

| 通道 | 内容 | 说明 |
|---|---|---|
| results | `runs/<id>/decisions.csv` | ≤ 20 MB。列固定为 `decision_id, slot_id, action, tile_id, program, request_id, reason` |
| agent | `pack_agent.py` 打出的 zip | ≤ 20 MB；模型 ≤ 128K 上下文；**每轮决策 ≤ 3 次大模型调用** |

- 每个场景分别排名，每队保留该场景**最高分**；严格同分先提交者在前。
- 额度：规则页写「每队每天最多 50 次」，`dev-reference` 榜单行写「上限/天 10」。**以页面实际显示为准**，规划实验时按 10 次/天排预算。
- 提交文件与详细运行结果只对本队和主办方开放，保留到颁奖日后 90 天。

## 数据与算力政策

- **不要求 GPU**。允许本地大模型、API 或纯算法；**不强制使用大模型**，确定性基线不需要任何密钥。
- 允许在本队设备/账号或大赛提供的平台上运行大模型（额度用完可找主办方切换备用模型）。
- **禁止**在评测期间调用外部平台上的 agent 服务。
- 模型密钥只用于自己授权的调用，**不得写入提交文件或公开代码**（`agent/.env` 已在 `.gitignore` 里）。
- 语言不限、算法不限。非 Python 实现走 JSON-Lines 标准输入输出协议，见 [agent-protocol.md](agent-protocol.md)。

## 红线（来自规则页与 SKILL.md）

保持尊重；不共享账号；不提交他人成果；不建多支队伍刷额度；不读取其他队伍私有数据；不篡改评分；不故意耗尽平台资源。

技术上第四条最容易踩：

1. 不读 `harness/scenarios/**` 里的任何文件来「反推」真值天气 —— 沙箱里也拿不到。
2. 不 import `agent/` 之外的东西。平台上 `challenge/` 包**不存在**，所以 `scoring_preview.py` 必须留在 `agent/` 里。
3. 不直接调 `ChallengeScorer.apply_decision` 探测评分器。
4. stdout 只准走协议行，日志一律 stderr。
5. 不构造当前候选集里不存在的 `(tile_id, program, request_id)`。

## 天文背景（帮自己建立直觉）

- **时隙 slot**：固定 900 秒时间片，每片只决定一次。
- **天区 tile**：切成网格的小块天区，是基本调度单位；**同一块天区可以重复拍**（正式规则取最高分）。
- **台址**：北纬 31.96°、西经 111.60°，UTC−7，太阳高度角 < −12° 才算夜。这些数字随场景 manifest 下发，换台址等于换题。
- **高度角 ≥ 30°** 才能合法观测；大气越垂直越好（airmass）。
- **月相**：满月附近明亮天区被月光淹没；`lunar_quality_factor ∈ (0,1]`，月亮在地平线下时为 1。
- **观测项目 DARK / BRIGHT / BACKUP**：暗区抢极暗窗口，亮区可容忍月光，备用项目填缝。天区有「暗/亮」属性，**只有选的项目等于质量算出来的档（band）才拿得到档位加成**。
- **观测请求 request**：限时任务，deadline 分 `ONE_WEEK / TWO_WEEKS / ONE_MONTH`，完成模式 `ALL / AT_LEAST_N`。
- **分区 region / REQUIRED / FLEXIBLE**：必做天区漏一块 −1000；每分区可选天区至少完成 4 块，每缺一块 −100。
- **仪器故障与临时事件**：云层 / 月亮山 / 台外光 / 强风 → 实时天况变差；7 天预报里有假阳性但**不含故障**。正式赛还有天区异常（引力微透镜 / 红化，乘性改变科学分）与故障上报。
