# ADR 0001 · 用 ADR 记录结构与合约决定

- 状态：已接受（2026-09-25）

## 背景

评测口径包含「代码质量、文档与展示」，且隐藏场景会改变规模、墙钟与规则代际。
这意味着两类决定特别贵：工作区结构（决定实验能不能复现）、以及合约假设
（决定策略会不会在隐藏场景上翻车）。这类决定改起来会牵连多处，事后从 git log 读不回来理由。

## 决定

在本目录留下简短 ADR，一篇一个决定，格式：状态 / 背景 / 决定 / 后果。
只写「以后会被问为什么这么干」的决定；日常实现细节不写。

## 后果

- 好处：合约类假设（例如「练习场景与正式场景是两代规则」）有明确的出处和代价记录。
- 代价：多一层文档维护。控制方式 = 保持每篇 30 行以内，且**不**在这里写教程（教程归 `docs/*.md`）。
